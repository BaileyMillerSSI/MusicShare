# Authenticated status v2

These four files are copied byte-for-byte to each app. SHA256SUMS hashes the schema, fixtures, and this document; do not reformat copies. No shared package or runtime service is required. Validate schema.json with a Draft-07 JSON Schema implementation and enforce the semantic rules below with the existing app/collector validation. fixtures.json contains full synthetic payloads: all valid cases must pass; schema-invalid cases must fail schema validation; semantic-invalid cases must fail the complete validator (a schema implementation may also reject them).

v2 preserves the v1 response fields and adds optional build.workflow {runId, url}. runId is a positive decimal string; url must be exactly https://github.com/<owner>/<repo>/actions/runs/<runId> with matching runId and no suffix, credentials, query, fragment or redirect. Omit workflow when unavailable. Build SHA identifies the exact checkout packaged into the server artifact. builtAt is UTC build preparation/start time, never app startup, request time, commit time, or completed deployment time. Stamp once immediately before the actual production build. Keep unknown sha/version/builtAt and deployment fields null. The workflow identifies the build-producing run; its presence does not claim that the workflow or deployment completed successfully.

All bounded text rejects control characters, including a final newline. Patterns use a portable strict end assertion because regex dollar anchors differ across runtimes. Additional semantic rules: timestamps must be real UTC calendar instants; components have unique names; coverage is exactly the set of component names; healthy requires at least one component and every component healthy. Metrics must be finite nonnegative numbers. The collector additionally binds service/environment to its registered app, filters metrics to reviewed keys, and applies freshness. Responses are capped at 32 KiB and duplicate JSON keys are rejected by the collector.

Keep existing bearer authentication and no-store headers. HEAD authenticates without dependency probes. No request-time provider calls or scans. Server-only build files must not enter public/static assets, VITE_* or NEXT_PUBLIC_* variables. Security snapshots are deliberately absent from v2: add a future version only when actual approved CI reporting exists, preserving scanned SHA/time/coverage and unknown/skipped states.

Rollout: deploy the collector accepting strict v1 and v2 first; then upgrade producers. v1 does not accept workflow. Old collectors reject v2. Local builds may return the unknown-build fixture shape; release builds must stamp exact build metadata.
