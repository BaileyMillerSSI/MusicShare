# CI/CD Pipeline — GitHub Actions + Azure Developer CLI

> **Slide talking points:** Push to main → production. That's it.

---

## The Pipeline at a Glance

```
Push to main (or manual trigger)
         │
    ┌────┴────┐
    │         │
Frontend   Backend
(Node 20)  (.NET 10)
  lint       restore
  build      build
             test
    │         │
    └────┬────┘
         │
      Deploy
   (if push/manual)
         │
    ┌────┴────┐
    │         │
Provision    Deploy
(azd prov)  (azd dep)
```

---

## Job 1 — Frontend

```yaml
- npm ci             # clean install
- npm run lint       # ESLint — no warnings allowed
- npm run build      # TypeScript check + Next.js build
```

- Catches type errors and lint issues before they hit production
- Next.js build also validates all routes and imports

---

## Job 2 — Backend

```yaml
- dotnet restore MusicShare.slnx
- dotnet build --configuration Release
- dotnet test --configuration Release
```

- Tests run against the Release build — catches any Release-specific issues
- xUnit with FluentAssertions — readable failure messages in CI logs

---

## Job 3 — Deploy (the interesting one)

### It uses `azd` — Azure Developer CLI

```yaml
- uses: azure/login@v2                  # OIDC login to Azure
- run: dotnet workload install aspire   # Aspire tooling
- run: azd provision --no-prompt        # Infrastructure (Container Apps, etc.)
- run: azd deploy --no-prompt           # Container images + app deployment
```

- `azd provision` reads `AppHost.cs` → generates Bicep → deploys Azure infrastructure
- `azd deploy` builds Docker images and pushes to Azure Container Registry
- **No Bicep files checked in.** Aspire generates them from the C# AppHost.

### Environment variables passed at deploy time

All secrets come from GitHub repository secrets/variables:
- MongoDB connection string
- RabbitMQ credentials
- Spotify API credentials
- Revalidation secret
- Custom domain + SSL certificate name
- Autoscaling limits (min/max replicas per service)

---

## Concurrency Control

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

- If you push twice in quick succession, the first deploy is cancelled
- Prevents two deploys racing each other to production

---

## Branch Strategy

| Branch | Deploy Target |
|--------|--------------|
| `main` | production environment |
| feature branches | no deploy (only build + test) |
| manual trigger on `main` | production (useful for re-deploying without code change) |

---

## What You Get For Free

- Every PR gets a full build + test run before merge
- Every merge to main deploys automatically
- Failed tests block deployment (jobs run in parallel but deploy waits for both)
- Manual re-deploy button available (`workflow_dispatch`)
- Full audit trail in GitHub Actions tab

---

## The "Zero Infra Work" Story

The entire Azure infrastructure — Container Apps environment, container registry, MongoDB connection, RabbitMQ, networking, custom domain with SSL — is:

1. Defined in `AppHost.cs` (C#, not YAML/Bicep/JSON)
2. Generated by Aspire at `azd provision` time
3. Updated automatically on every push to main

No Terraform. No Bicep. No CloudFormation. Just C#.
